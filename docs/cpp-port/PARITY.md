# C++ parity sweep (#409)

Feature-by-feature check of `loa-qt` against the shipped Rust app. Sources: every section of `docs/design/` (overview, gui, sessions, projects, surfaces, tools-and-mcp, models-and-providers, networking, updater, plus the shipped parts of `proposed-tools.md` and `feature-ideas.md`) and the five `README.md` "Experience and roadmap" items.

Status values:
- **done**: shipped in Rust (`crates/`), ported to C++, reachable from `loa-qt` (area registration, view, command or `--smoke` screen) and covered by a state, library or app test.
- **gap**: shipped in Rust but missing or unwired in C++; links its `CPP_PORT:` issue.
- **n/a**: design text only; the Rust code does not ship it, so it is not a parity target.

Result: 288 done, 0 gaps, 30 n/a. **No gaps were found**, so no `CPP_PORT:` gap issues were filed. Every `--smoke` screen is exercised by the `loa_qt_smoke_*` ctest entries; `QT_QPA_PLATFORM=offscreen ./build/app/loa-qt --smoke shell` exits 0.
