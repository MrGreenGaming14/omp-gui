The `omp2` branch exists, but the published releases (latest checked: v19.0.0) target `main`, not `omp2`. Do not treat this branch as a released RPC contract.

## Wire shape and sources

[`docs/adr/0003-one-authoritative-session-tree.md`](https://github.com/can1357/oh-my-pi/blob/2f92f3b5aa2035d21c9f016f9ff6350795e5685a/docs/adr/0003-one-authoritative-session-tree.md) calls the single DOM the authority: the journal records property-change transactions and replay materializes the tree. [`crates/dom/src/subscribe.rs`](https://github.com/can1357/oh-my-pi/blob/2f92f3b5aa2035d21c9f016f9ff6350795e5685a/crates/dom/src/subscribe.rs) defines `Patch {cause: EntryId, prior: Option<EntryId>, label: Option<Str>, ops: Vec<Op>}`. A replicated event is `{"kind":"patch@1","data":{"cause":"…","prior":null,"label":"todo.done","ops":[["set",412,"status","completed"]]}}`; see [collab replication](https://github.com/can1357/oh-my-pi/blob/2f92f3b5aa2035d21c9f016f9ff6350795e5685a/crates/driver/src/collab/session.rs). The closed [`Op` codec](https://github.com/can1357/oh-my-pi/blob/2f92f3b5aa2035d21c9f016f9ff6350795e5685a/crates/dom/src/op.rs) contains `["ins", parent, after|null, node]`, `["rm", handle]`, `["set", handle, prop, value]`, `["mv", handle, parent, after|null]`; `after=null` inserts first. Inserts mint monotonically increasing handles (not included in the insert op), so a translator must maintain the same high-water mark. Node specs carry `tag`, ordered `[prop,value]` pairs and optional `content`; see [`crates/dom/src/node.rs`](https://github.com/can1357/oh-my-pi/blob/2f92f3b5aa2035d21c9f016f9ff6350795e5685a/crates/dom/src/node.rs). The companion `stream@1` event has `cause`, `sid`, `op` (`open`, `append`, `close`), `node` and `prop` on open, `text` on append. `snapshot@1` replaces the replica on navigation; see [`snapshot.rs`](https://github.com/can1357/oh-my-pi/blob/2f92f3b5aa2035d21c9f016f9ff6350795e5685a/crates/dom/src/snapshot.rs).

The published [omp collab reference](omp://collab.md) describes the *main-branch* encrypted host/guest replication of entries, live events and state; it does **not** document omp2 `patch@1`. Likewise [RPC reference](omp://rpc.md) documents JSONL over stdio, but its public RPC events are message/tool updates, not omp2's private DOM subscription. The omp2 [`rpc_spine` tests](https://github.com/can1357/oh-my-pi/blob/2f92f3b5aa2035d21c9f016f9ff6350795e5685a/crates/app/tests/rpc_spine.rs) explicitly keep private journal patches out of public RPC events. There is no public RPC `set_dom_subscription` command or documented startup snapshot: this adapter's subscription request is an **assumption**, deliberately isolated in `crates/loa-adapter-omp2/src/wire.rs`, and startup fails with a version error when refused. No production end-to-end patch feed can be verified until omp2 exposes one. No released artifact of the Rust branch or public `stencil-hq/omp` repository was found.

## Mapping to this app's schema v1

The app's `loa-core` DOM is also single-writer and patch-based, but its `Draft` vocabulary is `Insert`, `Remove`, `Set`, `Append`; there is no move (translate by removal/reinsert). App inserts carry a new `NodeId` assigned by the sink and a positional index, whereas omp2 `ins` mints a handle and positions *after a sibling*. The adapter keeps a bidirectional handle/`NodeId` table and records `x-omp2-handle` for recovery. App patches have sequence and timestamp assigned by its writer; omp2's `cause`, `prior`, and label identify journal causality, not app sequence. Stream appends map directly onto app text appends. omp2's `<meta>`, `<body>`, `<assistant>` and provider-specific tool tags do not correspond 1:1 to schema v1: containers flatten, assistant content blocks become assistant messages, custom tool tags become calls, and other elements become `<ext harness="omp2">`; unknown properties become `x-` attributes. The translation table lives in `map.rs`. Native session journals use a different format from app patch journals; import/export is not advertised.

## Availability, models and effort

`Omp2Adapter::availability` runs the executable's `--version`, then opens an RPC session and sends the subscription: an `omp` that refuses it (every published omp, e.g. v19.0.0 answers `Unknown command: set_dom_subscription`) is reported `Incompatible`, so the harness picker lists omp2 without letting it be picked. `models()` uses `get_available_models` (`{models: [{id, name, provider, reasoning}]}`, verified in `crates/app/src/rpc_mode.rs` `rpc_models`); reasoning models offer the levels of `cycle_thinking_level` (`off` … `xhigh`), set with `set_thinking_level`.

## Re-check on each omp2 release

- Confirm the release/tag actually targets omp2 and whether `stencil-hq/omp` has become public; pin the tested commit.
- Diff DOM `Op`, `Patch`, `Event`, snapshot, tag/prop enums and high-water allocation; update `wire.rs` and mapping fixtures.
- Find a documented RPC or collab DOM subscription with initial snapshot and backpressure/reconnect semantics; replace the isolated assumed `set_dom_subscription` shape.
- Re-test ordering across snapshot, patch and stream, move/reparent, unknown props, resume and decisions against the released executable.
- Check main-branch [collab](omp://collab.md), [RPC](omp://rpc.md), and [session](omp://session.md) docs separately: none makes private omp2 patches public.
